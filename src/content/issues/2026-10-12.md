Every post this week names, before anything breaks, which part may degrade and which may not.
Meta sheds borrowed capacity before it touches baseline traffic and keeps its old ingest backend
behind a translator. Cloudflare holds a log batch rather than send it unredacted. Uber lets a fixed
rule overrule its model, and a Nepali ISP learned to treat IPv4 and IPv6 as separate planes.

---

## Meta moves Instagram Live ingest to MoQ and changes nothing downstream

Instagram Live now sends broadcasts from iOS and Android over Media over QUIC, an IETF draft Meta
helps write. It replaces RUSH, the in-house QUIC protocol that carried live ingest for nearly a
decade. MoQ models media as tracks of objects that relays cache and fan out without parsing
payloads, and two subscribers to one track can run at different latencies. The rollout design is
the part to study. One config parameter picks MoQ or RUSH per broadcast. MoQ terminates at
dedicated edge endpoints where a translator converts frames back to RUSH, so the backend is
untouched. Stream URL generation routes experiment groups server-side, so the ramp can be resized
in minutes without waiting on app adoption.

The post publishes no figures. The stated result is parity with RUSH on the quality and
reliability metrics used for the rollout, which was the goal. Two limits are named. UDP/443 is
still blocked on a non-trivial share of networks, so the TCP fallback still runs through RUSH. And
the team pinned draft versions while the spec kept moving.

## Meta spends idle inference capacity only on work it can drop in milliseconds

Meta's ads system pools idle accelerator and CPU capacity scattered across teams, regions and
hardware types. Two levers consume it. Rank More Ads raises how many candidates the ranking stages
evaluate, which needs CPU and accelerators. Serve Better Models routes more requests to a heavier
model, which needs only accelerators, so it can use surplus the first lever cannot. A PID
controller sets candidate volume from observed tail latency, and an explore-and-exploit router
decides which request segments get the heavier model.

The constraint is stated plainly: losing opportunistic capacity may cut optional work but must
never overload capacity reserved for baseline traffic. The central loops react in minutes and a
preemption can be faster, so servers and clients both shed the lowest-value optional work locally
within a few milliseconds. The post gives no numbers for capacity recovered or ad quality gained.
The pattern of making borrowed work the first thing shed is worth copying anywhere spare capacity
gets reused.

## A million-subscriber ISP found that IPv6 was really a DHCP project

WorldLink Communications in Nepal began testing IPv6 in May 2016, went live in July 2019, and now
runs more than a million IPoE subscribers, all IPv6-enabled, with about 70% of traffic on IPv6. Its
worst incident came from client behavior. Under RFC 8415 some routers ran a separate DHCPv6
transaction for the address and for the prefix, so the gateway saw two clients that never
completed. One router sent 116 SOLICITs in a minute. Delete-binding-on-renegotiation then tore
down live sessions, and the workaround that worked was an older router still following RFC 3315.

The lessons are concrete. Delegate a /56, not a /64. Report adoption as share of traffic, not
subscribers holding an address. Size gateways by whichever resource runs out first, such as
neighbor-discovery state. Get router and gateway vendors to agree in writing on the RFC before
deploying, because both ends being compliant did not make them compatible. This is one operator's
account, but anyone running DHCP at scale will recognize the failures.

[source →](https://blog.apnic.net/2026/10/12/seven-years-of-ipv6-in-production-lessons-from-one-million-broadband-subscribers/)

## Cloudflare's log transforms fail closed rather than ship raw data

Logpush Transformers attach a SQL query to an export job to filter, redact and reshape records
before they leave Cloudflare. The delivery service sends more than 110 million records per second.
A first prototype ran transforms in Workers, but that put a network hop in the export path, so
execution moved in-process on Apache DataFusion. The Go service hands batches to the Rust engine as
Arrow IPC over cgo, with memory ownership explicit on each side. A prepared transform processed a
synthetic 5,000-row batch in about 3 ms from one goroutine, roughly 1.6 million rows per second.

The failure policy is the choice to copy. If a transform cannot run, the service neither advances
the delivery offset nor sends the untransformed batch, because raw logs could break a downstream
redaction guarantee. Failing jobs back off and are eventually disabled. The benchmark is a single
goroutine on synthetic data, and the post does not say how much CPU a Transformer adds to a real
high-volume job.

[source →](https://blog.cloudflare.com/transformers-on-logpush/)

## Uber's contract agent lets fixed rules override the model

Uber's Legal Redlining Agent is a Word add-in that reviews counterparty edits, recommends accept,
reject or modify, drafts comments and flags risk. Uber reports more than a 20% cut in average
contract review time and 91% accuracy on AI-generated decisions. It took four iterations. Plain
retrieval over playbooks failed on relevance and tone. A store of lawyer decisions, weighted by
exponential decay with a 365-day half-life, let it adapt. Lawyers took over the tone prompt. A rules
index keyed on sentences from the source template finally made retrieval reliable.

The architecture splits hard and soft logic. A deterministic rule that matches a sentence overrides
the model, while tone and negotiation strategy come from the feedback loop. That let the tool ship
useful behavior on day one before feedback accumulated. The 91% figure has no stated evaluation
method, and the post covers a first-generation system built before current agent harnesses.

[source →](https://www.uber.com/us/en/blog/building-ubers-redlining-agent/)
