Four posts, one theme: a check is only as good as the context available where it runs. Cloudflare's tests saw status codes while a capacity mismatch leaked data. Meta's PrivacyLib evaluates policy in the caller, where purpose is still known. JiTTests check a change by executing it instead of reading it. Andromeda makes the same point about data movement: do the work where the bytes already are.

---

## Cloudflare's tests passed while a cache pool was smaller than the context window

Between August 27 and September 9, some responses from the GLM-5.3 model on Workers AI contained text from other users' sessions. Cloudflare counts 155 affected responses, all to prompts longer than 681,280 tokens. The model was deployed with a 1,048,576-token context window, while the KV cache pool on the prefill GPUs held only 681,280 tokens. The team knew about the gap before launch, and over-length requests returned a success status in testing, so they treated it as handled.

According to the post, a bug in SGLang's disaggregated prefill/decode mode then let over-length requests continue instead of aborting. Decode reserved more cache pages than prefill transferred and read the rest, which still held data from earlier requests. The client saw a normal response. The model was made private within about 40 minutes of the incident being declared on September 9, and restored that evening with a prefill pool of roughly 2.04 million tokens plus an engine patch.

Either fault alone was survivable. A pool sized to the full window never reaches the rejection path, and a correct rejection path turns the mismatch into a clean error. The transferable lesson is to compare every capacity number to the limit it has to cover, and to make load tests assert on output, not on status codes. ## Meta moves ads retrieval onto the GPU to remove the network hop

Meta says its Andromeda retrieval system now scores every eligible ad at over one billion ads per second, a 100x lift over the 2024 system. At that rate the bottleneck stopped being arithmetic. Intermediate tensor traffic to high-bandwidth memory and shipping candidate lists across the network dominated.

Two changes did the work. A mixture-of-experts retrieval model needs about 300x fewer inference FLOPs than the 2024 model, and that headroom paid for fusing embedding gather, interaction and scoring into one GPU kernel so intermediates stay in registers and shared memory. Separately, index matching (advertiser targeting rules) moved onto the same GPU server, which the post says cuts network traffic about 100x. INT8 gave up to 2x over FP16 with accuracy on par.

The cost is a redesign of index matching for GPU-parallel execution that still preserves targeting semantics. Several headline numbers are kernel-level benchmarks, and the post gives no latency percentiles or GPU counts. The sequencing is the part to copy: shrink the model first, then spend the savings on removing data movement. [source →](https://engineering.fb.com/2026/10/28/ml-applications/meta-andromeda-next-gen-ads-retrieval-gpu-co-design/)

## Meta's JiTTests run a generated test instead of reviewing the diff

Meta generates executable tests that demonstrate a concrete behavior difference a code change introduces, which it contrasts with LLM or agent code review. A pipeline selects risky diffs from the previous day and runs overnight on spare capacity. One workflow treats the diff as a mutant of its parent and writes tests that tell them apart. Another has an LLM infer the diff's intent, builds mutants from the risks, and writes tests to catch them. Tests that fail on the real diff are kept as weak catches.

A weak catch is often a false positive, so an ensemble of LLM judges and a deterministic rule-based filter classify and rank them. Engineers review outcomes in aggregate rather than supervising each one. Meta reports 589 engineers engaged, a 60% true-positive rate as reported by those engineers, 74 serious privacy bugs caught at the diff stage in the first half of 2026, and a 20% drop in privacy incidents over the same period.

The authors state the limits: it takes more computational steps than LLM review, judge output is non-deterministic, and the post gives no compute cost. The 60% is engineer-reported, not an audited precision, and the 20% drop is not a controlled comparison. The deterministic layer beside the LLM judges is the design choice worth borrowing. [source →](https://engineering.fb.com/2026/10/29/security/catching-bugs-before-they-land-jittestings-human-on-the-loop-approach-at-full-scale/)

## PrivacyLib evaluates policy where the caller's purpose is still known

Meta used to implement each privacy requirement separately in each data system's client. PrivacyLib is a common library running inside the clients of hundreds of data and processing systems. Each system integrates once and requirements ship as modules, either enforcing (Policy Zones can block an access) or observing (Privacy Probes record it). Meta cites billions of checks per second across thousands of production services. Most checks are answered from in-process caches, and the authors say an earlier remote config fetch was thousands of times slower.

Rollout is treated as a safety problem. Annotation changes are reviewed by replaying observed data flows against the old and new artifacts, and module changes move from 0 to 100% behind a runtime control that can be lowered without a redeploy. Direct RPCs that skip the client carry a signed token from a prior check, and requests without one get a coarser check because the authors prefer false positives over gaps. For AI agents, tool calls carry session context to the same boundary.

The costs are admitted. In-process evaluation propagates changes more slowly than a global config push, an invalid config once crashed processes fleet-wide, and annotation changes that compiled cleanly altered access decisions and caused product failures. Paths outside the supported boundaries are not covered. The post gives almost no performance baseline. [source →](https://engineering.fb.com/2026/10/27/security/privacylib/)
